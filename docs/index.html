Architecture

From raw files to contracts

Each layer has one job. Staging only types and reshapes (wide files to long, JSON to rows). Intermediate holds every business rule, each in one place: what a duplicate is, what an injury episode is, how heart-rate zones are computed. Marts are the only tables anyone reads: every column is documented and their types are enforced, so a change that would break a consumer fails the build instead.

Quality

What the rules found in the published dataset

Daily load ≠ its sessions

On 110 player-days (3 players) the provider's daily load is higher than the sum of the sessions it was computed from, never lower: sessions are missing from the export. The warehouse recomputes the load from the sessions it has.

assert_provider_daily_load_reconciles

Heart rate frozen at 82 bpm

2,871 recordings show one value for most of the session, the strap's default. It passes every range check; the share of time at a single value catches it.

hr_quality_flag = frozen_sensor

Players pseudonymised twice

28 players have GNSS data but no questionnaire, under another UUID format. A linkage on attendance was tried: teammates train on the same days, so it cannot tell them apart. No link is guessed.

assert_gps_players_are_known

Two recordings, one file name

81 file names hold two different recordings (distance and duration differ). Nothing says which one is the player's: both are quarantined.

gps_quality_flag = duplicate_file_name

Player missing inside the file

3 recordings have an empty player column although the file name carries the identifier. It is recovered from the name, by a rule that stays visible.

assert_gps_player_from_file_name

Duplicates

76 exact repeat sessions and 6 injury reports submitted twice, flagged in staging and removed in one documented model.

is_exact_repeat

Quarantine, not deletion

Every recording keeps its row and gets two flags. Indicators are computed on valid data only: 1,323 recordings have usable heart rate; 271 were set aside (unit left recording all day, GNSS jump).

Personal data

Health data, handled as such

  • Health data is a special category under GDPR (art. 9), pseudonymised or not.
  • Players are pseudonymised by the provider; no other identifier enters the warehouse.
  • Every published column carries a sensitivity tag (operational pseudonymised identifier health) that an access policy or a BI tool can read: the medical staff sees injury episodes, a coach sees availability.
  • The raw 100 Hz files are never stored, only the features needed downstream.
